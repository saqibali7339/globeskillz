How to Upload an HTML File to Shopify for Search Console

Google Search Console asks you to upload an HTML verification file, but Shopify gives you no access to your store root. This guide explains why the file method fails on Shopify and walks through the two methods that do work: the HTML meta tag in theme.liquid and the DNS TXT record.

If you are setting up Google Search Console for a Shopify store, Google offers you a choice: upload an HTML file to your site, add an HTML tag, add a DNS record, or connect Google Analytics. The file option looks like the simplest one, so most store owners pick it first. Then they hit the same wall: there is nowhere in Shopify to upload it.

Shopify does not give merchants access to the root directory of their store, so the file method cannot work. This guide explains why, then walks through the two methods that do work on Shopify, the meta tag and the DNS record, plus what to do when verification fails.

The short answer

You cannot upload an HTML verification file to Shopify for Search Console. Shopify gives you no access to your store root, and files uploaded in the Shopify admin land on Shopify's CDN, not at your domain, so Google never finds the file where it looks for it.

Use one of the two methods that work instead. The fast method is the HTML meta tag: add a URL-prefix property in Search Console, copy the meta tag, paste it into theme.liquid, and click Verify. The durable method is the DNS TXT record: add a Domain property, copy the TXT record, add it where your DNS lives, and click Verify. Both prove ownership the same way, and Google treats them as equal. The steps for each are in sections 3 and 4.

Why the HTML file upload does not work on Shopify

Google's file method works like this: Search Console gives you a verification file, you place it in the root folder of your website, and Google checks that it exists at your domain under that file name. On a normal host you would upload it with FTP or a file manager. Shopify has no FTP and no root folder access for merchants.

The only file upload Shopify offers is Content, then Files in the admin, and that stores files on Shopify's CDN at an address like cdn.shopify.com, not at your store domain. Google looks for the file at your domain, so a file on the CDN does not count. Shopify's own help docs point store owners to the meta tag method instead, and Google accepts it as a full equivalent for ownership verification.

This is not a plan limitation. It applies on every Shopify plan, from Basic to Plus. If a guide tells you to upload the verification file to Shopify, it is describing a step that does not exist on this platform. This walkthrough of the Shopify verification problem reaches the same conclusion: the file method is a dead end, and the meta tag is the fix.

Method 1: verify with the HTML meta tag in theme.liquid

This is the fastest method, and it takes about two minutes. You need a URL-prefix property, not a Domain property, because only the URL-prefix type accepts the HTML tag.

Step 1: open Google Search Console and click Add property. Choose URL prefix and enter your full store address, including https, exactly as it loads. On the verification screen, open the HTML tag option and copy the full meta tag. It starts with a meta name of google-site-verification and ends with a long content value. Copy the whole tag, not just the code inside it.

Step 2: in your Shopify admin, go to Online Store, then Themes. Find your live theme, open the three-dot menu next to it, and choose Edit code. In the Layout folder, open theme.liquid. This is the master template that wraps every page of your store, so anything in its head section appears on every page Google crawls.

Step 3: paste the meta tag on its own line just below the opening head tag, then click Save. Theme edits publish at once, so go back to Search Console and click Verify. It usually passes on the first try.

One warning: the tag lives in your theme, so it disappears when you publish a new theme or switch to a different one. Google re-checks ownership from time to time, and a theme change can silently break verification days later. If you change themes, paste the tag into the new theme before you publish it. That weakness is the main reason the DNS method in the next section is the better long-term choice.

Method 2: verify with a DNS TXT record

This is the method we recommend, because it survives theme changes, redesigns, and app installs. It verifies a Domain property, which covers your whole domain at once: www and non-www, http and https, and every subdomain, in one property.

Step 1: in Search Console, click Add property and choose Domain. Enter your bare domain with no https and no www, for example yourstore.com. Google shows you a TXT record that starts with google-site-verification=. Copy the full value.

Step 2: add the record where your DNS lives. If you bought the domain through Shopify, go to Settings, then Domains, click the domain, open DNS settings, choose Add custom record, pick TXT, and paste the value. If you bought the domain at GoDaddy, Namecheap, Cloudflare, or another registrar, add the TXT record in that provider's DNS panel instead.

Step 3: go back to Search Console and click Verify. DNS changes can take a few minutes or a few hours to spread, and Google says a new record can take up to two or three days to be served. If it fails, wait and try again rather than adding a second record. Once it passes, leave the TXT record in place. Google says to keep it there to stay verified, and deleting it can break verification later.

Other ways to verify: Google Analytics and Tag Manager

A URL-prefix property can also be verified through Google Analytics or Google Tag Manager, if the same Google account has edit access to the Analytics property or the Tag Manager container, and the matching tag is already installed on your store. For most Shopify stores this means the Google and YouTube app, or a GA4 tag added to the theme.

These methods work, but they add a dependency: if the Analytics tag or the Tag Manager container is removed, verification breaks. They are useful when you already have Analytics running and cannot reach your DNS or your theme code, but they are not more reliable than the meta tag or the DNS record. If you are setting up Analytics at the same time, our guide to adding Google Analytics 4 to Shopify covers the install first.

Submit your Shopify sitemap after verification

Verification only proves you own the store. It does not tell Google which pages to crawl. Shopify builds your sitemap for you at yourdomain.com/sitemap.xml, an index file that links to sub-sitemaps for products, collections, pages, and blog posts, and it updates as your catalog changes.

In your new Search Console property, open Indexing, then Sitemaps, type sitemap.xml in the Add a new sitemap box, and click Submit. You submit only the index file, not each sub-sitemap. Google then starts reading your pages, and your reports begin to fill in over the next few days. New stores should also check that the store is public first: while the password page is on, Google cannot read your pages or your sitemap at all.

What to do when verification fails

Most failures come from one of five causes. First, the store is still password protected. Turn the password page off before you verify. Second, the meta tag went into the wrong theme. Only the live, published theme counts, so check the tag is in the theme your store actually uses.

Third, the DNS record has not spread yet. Wait a few hours and try again, and do not add a second record while you wait. Fourth, the property type and the method do not match: a Domain property accepts only a DNS record, so the HTML tag option never appears for it, and a URL-prefix property is the one that accepts the tag.

Fifth, the tag was copied wrong. A missing character, an extra space, or a tag pasted outside the head section all fail silently. Copy the full tag again, paste it on its own line in theme.liquid, save, and verify again. If the tag method keeps failing, switch to the DNS record. It avoids the theme entirely, so most theme-related failures disappear with it.

Frequently asked questions

Can I upload the Google verification file to Shopify?

No. Shopify gives merchants no access to the store root, so there is nowhere to place the file. Files uploaded in the Shopify admin go to Shopify's CDN, not to your domain, and Google looks for the file at your domain. Use the HTML meta tag in theme.liquid or the DNS TXT record instead.

Which verification method is best for Shopify?

The DNS TXT record with a Domain property. It covers your whole domain in one property and survives theme changes, redesigns, and app installs. The HTML meta tag is faster, about two minutes, and works well if you need verification today and cannot reach your DNS.

Will changing my Shopify theme break verification?

Yes, if you verified with the HTML meta tag. The tag lives in theme.liquid, so publishing a new theme removes it, and Google can un-verify the property days later. Paste the tag into the new theme before you publish it, or verify with a DNS record, which a theme change cannot touch.

How long does Search Console verification take?

The meta tag method is usually instant once the tag is saved. The DNS method can take a few minutes to a few hours, and Google says a new record can take up to two or three days to be served. After verification, your reports still take a few days to fill in, and older data is not backfilled.

Do I need to keep the verification tag or DNS record?

Yes. Google re-checks ownership from time to time, so leave the meta tag in theme.liquid or the TXT record in your DNS in place. Removing it can break verification, and you would have to verify the property again from the start.
